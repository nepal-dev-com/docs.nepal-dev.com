## Trigger

Any commit that lands on `main` (a push, a merged pull request, a commit made on GitHub), from the owner or from a consuming
repository (ADR-0042, ADR-0043). Vercel's production branch is `main`, so each one is a production deployment on the custom
domain. `vercel.json` gives every other branch no deployment (`git.deploymentEnabled`), and nothing cancels a commit on `main`.

The build is `vercel.json`'s `buildCommand`: `sh scripts/require-full-history.sh && bun run build`. `bun run build` runs `next build`,
then `node --env-file-if-exists=.env.local scripts/sync-content.ts`. On Vercel there is no `.env.local`; the variables come from
the Production environment.

## Failure paths

Every failure below fails the deployment, so the previous one stays live.

| Step | Failure | Behaviour | Recovery |
|---|---|---|---|
| 1 | A push to any branch but `main` | No deployment; nothing is built or synced | Merge to `main` |
| 1 | A fork's pull request (Vercel asks for authorization, Git Fork Protection), or a `vercel` CLI deploy | Not authorized: no build. Authorized, or from the CLI: it builds with no variables, the sync refuses at step 8, and nothing is published | Merge to `main`; don't authorize fork deployments |
| 3 | `bun.lock` does not match `package.json` | `--frozen-lockfile` fails the install | Update the lockfile locally (with the owner's yes), push |
| 3 | The clone is shallow (`VERCEL_DEEP_CLONE` unset or ignored) | `require-full-history.sh` exits `1`, naming `VERCEL_DEEP_CLONE` and ADR-0042; nothing is built | Set `VERCEL_DEEP_CLONE=true` in Production, redeploy |
| 5 | Invalid MDX or frontmatter | `next build` fails; the sync never runs | Fix the page, push |
| 8 | `SITE_URL`, `NEXT_PUBLIC_ALGOLIA_APP_ID` or `ALGOLIA_WRITE_KEY` missing | The script throws before reading anything, naming every missing variable and no value; the index is unchanged (ADR-0042 decision 7) | Set the variables in Production, redeploy |
| 8 | `static.json.body` not found (unknown build adapter layout) | The script throws reading an undefined path; the index is unchanged | Check the build output layout; adjust the glob |
| 10 | Algolia rejects or is unreachable | The script fails after a successful `next build` | Redeploy |

## Post-conditions

- The Algolia index `document` holds exactly the pages in this build, which is every page in `content/` on `main`. Anyone with
  the public search-only key can query all of them.
- The sync finishes before Vercel makes the deployment live, so for that short gap search can find a page that is not served yet.
- Vercel's *Instant Rollback* brings back old pages but not the old index. A `git revert` pushed to `main` moves both (ADR-0042
  decision 9).
