## Inventory

The variables are read directly where they are used. In production they live in Vercel's
Production environment, and Preview and Development hold none; `ALGOLIA_WRITE_KEY` is marked
*Sensitive*, so it cannot be read back from the dashboard (ADR-0042). Locally they live in
`.env.local`, which `.gitignore` excludes (`.env*.local`). `.env.example` at the repository root
lists every variable below, with a comment and no value.

| Variable | What it is | Secret? | Reaches the browser? | Read by | Rotation |
|---|---|---|---|---|---|
| `SITE_URL` | The site's public address, an `https` origin with no path; without it every page is `noindex` (ADR-0035) | No — public, and printed on every share image | Only as the address in pages' links and images; never as a variable | `src/lib/seo.ts`, `src/app/og/[...slug]/route.tsx`, `scripts/sync-content.ts` (through `src/lib/publish-env.ts`) | When the domain changes |
| `NEXT_PUBLIC_ALGOLIA_APP_ID` | Algolia application ID | No | **Yes**, inlined into the client bundle | `src/lib/algolia.ts`, `scripts/sync-content.ts` (checked by `src/lib/publish-env.ts`) | With the Algolia application |
| `NEXT_PUBLIC_ALGOLIA_SEARCH_KEY` | Algolia search-only API key | No — public by design, but it can read **every record** in the index | **Yes**, inlined into the client bundle | `src/lib/algolia.ts` | On suspicion of abuse, in the Algolia dashboard |
| `NEXT_PUBLIC_GA_MEASUREMENT_ID` | Google Analytics 4 measurement ID; unset or empty turns off Google Analytics, the banner and the footer link; a malformed value fails the build (ADR-0041) | No — public by design | **Yes**, inlined into every page and its inline script | `src/lib/privacy-choice.ts` | With the GA4 property; set in the host's Production environment only |
| `VERCEL` | Set by Vercel at build; when present, Vercel Web Analytics and Speed Insights render (ADR-0041). Never set by hand | No | No | `src/app/layout.tsx` | — |
| `VERCEL_DEEP_CLONE` | Set to `true` in Vercel's Production environment only, so the build clones the full history for `lastmod`; undocumented by Vercel, so `scripts/require-full-history.sh` fails a shallow build (ADR-0042) | No | No | Vercel's clone step; checked by `scripts/require-full-history.sh` | — |
| `ALGOLIA_WRITE_KEY` | Algolia key with write access to the index | **Yes** | No | `scripts/sync-content.ts` only (checked by `src/lib/publish-env.ts`) | On suspicion, or yearly, in the Algolia dashboard |

## Rules

- **No secret is ever a string literal** — not in source, config, comments, tests or docs.
- **`NEXT_PUBLIC_*` publishes a value to every browser.** Never a secret; each one is reviewed
  as a publication. `ALGOLIA_WRITE_KEY` must never gain the prefix.
- **`.env*.local` files stay out of git.** `.env.example` is committed and documents every
  variable with a comment, never a value.
- **A build that publishes refuses to run without the secrets it needs**, naming the variable
  and never printing its value. `scripts/sync-content.ts` refuses without `SITE_URL`,
  `NEXT_PUBLIC_ALGOLIA_APP_ID` or `ALGOLIA_WRITE_KEY` before reading anything, naming each missing
  one (ADR-0042 decision 7), so production can neither go `noindex` silently nor half-publish.
- **If a secret is ever committed, rotate it immediately.** Removing it from the tree or from
  history is not enough.
