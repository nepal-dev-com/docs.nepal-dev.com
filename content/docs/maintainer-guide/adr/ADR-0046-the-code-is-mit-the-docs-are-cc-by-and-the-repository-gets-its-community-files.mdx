## Context

- The repository has no `LICENSE`, and `package.json` has no `license` field. Without a licence nobody
  else may reuse the code or the pages, and a project that writes its documentation here
  (ADR-0010) has no stated terms for it.
- It has no `CONTRIBUTING.md`, code of conduct, security policy or `.github/` folder. `README.md`
  carries the whole process, the deploy settings and the site's design in one long file.
- The owner is nepal-dev.com, and [@puncoz](https://github.com/puncoz) maintains the site (ADR-0039).
- `.agent-skills/` holds third-party skills under their own licences (ADR-0009, ADR-0045), and
  `assets/` holds nepal-dev.com's logo.
- Only `main` deploys, and a fork's pull request gets no deployment (ADR-0042).
- The owner chose, when asked on 2026-11-14: MIT for code with CC BY 4.0 for documentation; the
  holder "nepal-dev.com and contributors"; all four community files; contributors shown as a README
  section linking GitHub's contributors page.

## Decision

1. **The code is MIT.** `LICENSE` holds the MIT licence, "Copyright (c) 2026 nepal-dev.com and
   contributors". It covers everything not named in decisions 2 and 3. `package.json` gets
   `"license": "MIT"`.
2. **The documentation is CC BY 4.0.** `LICENSE-CONTENT` holds the Creative Commons Attribution 4.0
   International legal code, unchanged. It covers the pages in `content/` and the diagrams in
   `diagrams/`. A project that adds pages here publishes them under it; `PROJECT_AGENTS.md` §2 says so.
3. **What neither licence covers:** the skills in `.agent-skills/` that come from elsewhere, each
   under the licence in its own folder (`SOURCES.md`); the nepal-dev.com name and logo, the logo
   file in `assets/` and the brand mark drawn from it; and code examples inside a page, which are MIT
   so they can be copied into code without attribution.
4. **`README.md` is rewritten in the usual GitHub shape:** what it is, features, quick start, scripts,
   project structure, documenting a project, contributing, maintainers and contributors, security,
   licence. The deploy settings and the description of the look stay in the Maintain track, which
   the README links to.
5. **`CONTRIBUTING.md`** states the existing process (the ADR gate, tests and docs in the same change,
   never guess, how a project documents itself) for people, and points to `AGENTS.md` as the
   authority. It adds no rule.
6. **`CODE_OF_CONDUCT.md`** is the Contributor Covenant 2.1, unchanged apart from the contact:
   reports go to the maintainer, [@puncoz](https://github.com/puncoz), through the contact on that
   GitHub profile.
7. **`SECURITY.md`** asks for reports through GitHub's private vulnerability reporting, never a
   public issue, and covers private content that reached a public surface as well as flaws. No
   email address is published.
8. **`.github/`** holds issue forms (a bug, a documentation problem, a proposal that leads to an
   ADR), with blank issues off and a link to the security policy; a pull request template with the
   checklist of `AGENTS.md` §11; and `CODEOWNERS` naming `@puncoz` for everything. No workflow: CI
   needs its own ADR.
9. **Contributors** are a README section: the owner, the maintainer, and a link to GitHub's
   contributors page. No hand-kept list and no image from a third-party service.

## Options considered

| Option | Pros | Cons | Verdict |
|---|---|---|---|
| A — MIT for code, CC BY 4.0 for pages | Each kind of work under a licence made for it; pages can be shared with credit | Two files to explain | Chosen |
| B — MIT for everything | One file | Written for software; unclear for documentation other projects write | Rejected |
| C — Apache-2.0 for everything | Patent grant | Heavier than needed; same weak fit for text | Rejected |
| D — No licence | Nothing to decide | Nobody may reuse anything | Rejected |
| E — A `CONTRIBUTORS.md` list | Names in the repository | One name today; goes stale | Rejected |
| F — An avatar grid from contrib.rocks | Familiar | A third-party image on every view | Rejected |

## Consequences

**Positive**

- Anyone may use the code, and share or adapt the documentation with credit.
- A newcomer finds how to run, contribute and report in the places GitHub shows them.
- The README is short enough to read.

**Negative / accepted trade-offs**

- A licence cannot be withdrawn from copies already taken.
- Every contributor of pages accepts CC BY 4.0 for them; a project that cannot must not publish here.
- The contributing guide repeats rules from `AGENTS.md`, and must be kept in step with it.
- `CODEOWNERS` asks `@puncoz` for review on every pull request.

## Content invariants

None changed. §6.1 stands: a licence is about reuse, not privacy, and nothing private goes into
`content/` whatever its licence.

## Security considerations

No code path, endpoint or secret is touched. `SECURITY.md` gives private reporting a place, which
the repository lacked; it works only once the owner switches on private vulnerability reporting in
the repository's settings. The policy tells a reporter of leaked private content that published is
permanent, and to report at once. No email address or other personal data is added. Issue forms ask
reporters not to paste secrets or private content.
