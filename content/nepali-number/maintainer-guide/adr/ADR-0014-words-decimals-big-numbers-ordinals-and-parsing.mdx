## Context

This ADR builds on
[ADR-0012](./ADR-0012-read-every-number-once-exactly.mdx): the `NumericInput` type, the exact
decimal-string reading of every number, the one invalid-input rule and the rounding rule. It
applies them to the `words` domain and adds what the domain lacks.

What the four exports do today, run against the built package:

- **Decimals have no words.** `toNepaliWords(12.5)`, `toEnglishWords(12.5)` and
  `toNepaliOrdinal(12.5)` return `""`, because the word tables are indexed by the number.
  `toNepaliWords("12.0")` returns `"बाह्र"` while `toNepaliWords("12.50")` returns `""`.
- **Big numbers are wrong without saying so.** Input goes through `parseFloat`, so
  `toNepaliWords("12345678901234567890")` ends in `"… सतसट्ठी हजार एक सय अठसट्ठी"`; the real
  last digits are `…67,890`. A `bigint` is accepted at run time (not by the types) and loses
  the same digits.
- **Invalid input reads as zero.** `toNepaliWords("abc")` → `"शून्य"`, `toEnglishWords("abc")` →
  `"zero"`, `toNepaliOrdinal("abc")` → `"शून्यौं"`, `toDecimalWord("abc")` → `"०"`.
- **`toDecimalWord` does not abbreviate negatives.** `toDecimalWord(-1200000)` →
  `"-१२,००,०००"`.
- **Every recursive step parses again.** `toNepaliWords` turns its number into a string and
  parses it on each level of the recursion.
- **Three fallbacks are unreachable** (`return String(number)` after the scale loop), which is
  the only uncovered code in the package.
- **There are no English ordinals, no digit ordinals (`५औं`, `5th`), no international
  (million, billion) English, and no way back from words to a number.**

One thing is noticed and deliberately left alone. The language data in `src/constants.ts` is
not consistent with itself: `NEPALI_WORDS[19]` is `उन्नाइस` while `NEPALI_ORDINALS[19]` is
`उन्नाईसौं`; the scale `पद्म` has the ordinal `पदमौं`; `अर्ब` has `अरबौं` and `खर्ब` has
`खरबौं`. Which spelling is right is the owner's call (ADR-0004), and every one of them is an
output string. **This ADR changes no existing word.** A spelling review of the 0–99 words, the
ordinals and the scale labels is a follow-up ADR of its own.

## Decision

Written on the recommended option of every row in *Owner decisions* below; each is assumed
until the owner picks.

### Shared behaviour

- Every export that reads a number takes `NumericInput` (`number | bigint | string`) and reads
  it once, exactly (ADR-0012). The recursion works on digit strings, with no re-parsing.
- Invalid input returns `""` from the string-returning exports and `NaN` from the two parsers
  (ADR-0012, decision D1).
- The three unreachable fallbacks are removed.

### Changed exports

```ts
toNepaliWords(number: NumericInput): string
toEnglishWords(number: NumericInput, options?: EnglishWordsOptions): string
toNepaliOrdinal(number: NumericInput): string
toDecimalWord(number: NumericInput, options?: DecimalWordOptions): string
```

- **`toNepaliWords`** reads a fraction digit by digit after `दशमलव`; trailing fraction zeros
  are dropped, so `"12.0"` and `"12.50"` read as `12` and `12.5`. Above महाशंख the count
  recurses (`10n ** 21n` → `"एक सय महाशंख"`).
- **`toEnglishWords`** reads a fraction digit by digit after `point`, and takes options:

  | Option | Type | Default | Effect |
  |---|---|---|---|
  | `system` | `"nepali" \| "international"` | `"nepali"` | `"international"` uses thousand, million, billion … decillion (10³³), recursing above |
  | `hyphenate` | `boolean` | `false` | `true` joins tens and ones: `"twenty-three"` |
  | `and` | `boolean` | `false` | `true` puts `and` after `hundred` when something follows: `"one hundred and twenty three"` |

- **`toNepaliOrdinal`** keeps every integer output; a non-integer or invalid input returns
  `""`.
- **`toDecimalWord`** abbreviates negatives, and takes options:

  | Option | Type | Default | Effect |
  |---|---|---|---|
  | `precision` | `number` | `2` | Decimal places when the value is not an exact multiple of its scale; not an integer in 0–100 → `2` |
  | `useNepaliDigits` | `boolean` | `true` | `false` keeps English digits; the scale label stays Nepali |

### New exports

```ts
toEnglishOrdinal(number: NumericInput, options?: EnglishWordsOptions): string
toNepaliOrdinalNumber(number: NumericInput, options?: OrdinalNumberOptions): string
toEnglishOrdinalNumber(number: NumericInput, options?: OrdinalNumberOptions): string
parseNepaliWords(words: string): number
parseEnglishWords(words: string): number
```

- **`toEnglishOrdinal`**: the cardinal from `toEnglishWords` with its last word made ordinal
  (`first`, `second`, `third`, `fifth`, `eighth`, `ninth`, `twelfth`, `twentieth`, otherwise
  `-th`). Zero is `"zeroth"`; a negative is `"negative …"`; a non-integer returns `""`.
- **`toNepaliOrdinalNumber`**: digits and a suffix, `लो` `रो` `रो` `थो` for 1–4 and `औं` from 5,
  with no grouping. `OrdinalNumberOptions` is `{ useNepaliDigits?: boolean }`, default `true`.
  A non-integer, a negative or invalid input returns `""`.
- **`toEnglishOrdinalNumber`**: digits and `st` / `nd` / `rd` / `th`, chosen by the last two
  digits (11, 12 and 13 take `th`). `useNepaliDigits` defaults to `false` here.
- **`parseNepaliWords`**: the inverse of `toNepaliWords` for the words in `src/constants.ts`:
  an optional `ऋण`, scale groups from large to small, and an optional `दशमलव` followed by
  digit words. Anything else returns `NaN`.
- **`parseEnglishWords`**: case-insensitive; accepts hyphens, `and`, and the scales of both
  systems. Anything else returns `NaN`.

### Language data added to `src/constants.ts`

`दशमलव`; the ordinal digit suffixes `लो`, `रो`, `रो`, `थो`, `औं`; English `point`, the
international scale names, and the irregular English ordinal words.

## Options considered

| Option | Pros | Cons | Verdict |
|---|---|---|---|
| A — Extend the four exports in place and add five beside them | One name per job; fixes land where people already call | Output changes for decimals, invalid input and negatives | Chosen |
| B — Leave the four untouched; add `toNepaliDecimalWords`, `toNepaliWordsExact` … | No output change | Two functions for every job; the wrong ones stay the obvious ones | Rejected |
| C — One `toWords(number, { language, form })` | Fewer names | Replaces four published names; `language` contradicts the Nepali-only decision | Rejected |
| D — Fix the inconsistent spellings here as well | One review | Mixes language decisions with API decisions; each spelling is its own output change | Rejected: follow-up ADR |

## Consequences

**Positive**

- Decimals, exact big numbers and negatives work in every word function.
- Words can be read back into a number, which makes form input and tests possible.
- The domain reaches full coverage: the unreachable fallbacks are gone.

**Negative / accepted trade-offs**

- The minified build grows: five exports, the international scale names, the English ordinal
  words and two parsers. The number is measured at implementation (invariant 8).
- `parseNepaliWords` and `parseEnglishWords` return a JavaScript `number`, so a parsed value
  above 2⁵³ is not exact. Documented in the reference.
- `parseNepaliWords` reads only the spellings in `src/constants.ts`. A variant spelling is
  `NaN` until the spelling review decides whether variants are accepted.

**For consumers**

- Code that relied on `""` for a decimal, or on `"शून्य"` / `"zero"` / `"शून्यौं"` / `"०"` for
  invalid input, sees a different string. Check validity with `isValidNumber` (ADR-0013)
  instead of comparing with the zero word.
- Code that added its own minus sign in front of `toDecimalWord(Math.abs(n))` keeps working.
- Every integer output documented today is unchanged.

## Package invariants

- **1, 2, 3** — no dependency, no host global, no state: kept.
- **4 — no throwing.** Every new and changed export returns `""` or `NaN` for invalid content.
  `bigint` becomes a declared input type.
- **5 — output strings are the contract.** The changes are listed in the before/after table
  and are absorbed by the unreleased 2.0.0.
- **6 — language data has one home.** `दशमलव`, the suffixes and every English word go into
  `src/constants.ts`; the parsers build their lookup from the same tables, so a word can never
  be written by one function and unreadable by the other.
- **7 — Unicode-aware.** The parsers split on whitespace and compare whole words; no `\d`, no
  `.length` arithmetic on Devanagari.
- **8 — small.** Grows; measured at implementation.
- **Layering** is unchanged: `words` imports `conversion`, `formatting` and `utils`.

## Security considerations

- **New input parsing.** `parseNepaliWords` and `parseEnglishWords` read untrusted strings.
  Both are single-pass scanners over whitespace-separated tokens with a table lookup per
  token: no regular expression with a quantifier over unbounded input, so time is linear. Each
  is tested with a 100 000-character hostile string (one long token, and 50 000 valid tokens).
- **Recursion depth.** The word builders recurse once per scale group. Input length is
  bounded by the core reader (ADR-0012), so depth is bounded too; the test uses a
  1 000-digit `bigint`.
- Empty, whitespace-only, huge, `NaN`, `Infinity` and non-digit input have a defined, tested
  and documented result.
- No dependency, no CI or publishing change, no logging.
