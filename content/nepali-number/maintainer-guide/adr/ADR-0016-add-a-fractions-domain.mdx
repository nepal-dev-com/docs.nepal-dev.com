## Context

Nepali does not usually say half and quarter amounts as decimals. One and a half is `डेढ`, two
and a half is `अढाई`, three and a half is `साढे तीन`; a fraction on paper is read
`दुई बटा पाँच`; twice as much is `दोब्बर`. The package has no export for any of these: today a
consumer who needs them writes the table themselves.

What the package returns today for the same values, run against the built `dist/nepali-number.cjs`:

| Call | Today |
|---|---|
| `toNepaliWords(0.5)` | `""` |
| `toNepaliWords(1.5)` | `""` |
| `toNepaliWords(2.5)` | `""` |
| `toNepaliWords(2)` | `"दुई"` |

This ADR builds on two others and cannot be implemented before them:

- [ADR-0012](./ADR-0012-read-every-number-once-exactly.mdx) — the exact decimal reader,
  `NumericInput`, and the one invalid-input rule (a string-returning export returns `""`).
  Quarter steps are recognised on the decimal digits as written, so `0.25` is a quarter with
  no floating-point test.
- [ADR-0014](./ADR-0014-words-decimals-big-numbers-ordinals-and-parsing.mdx) — decimal words
  (`दशमलव`), which this domain falls back to for a value that is not a quarter step.

The owner put fractions and multipliers in scope on 2026-11-14, and decided the package is
Nepali only: there is no language option here.

**Every Devanagari string this ADR introduces is the recommendation of the drafting agent. None
was verified against a dictionary or a style reference. Each needs the owner's confirmation
before this ADR is approved** (`AGENTS.md` §4); they are listed under *Owner decisions*.

## Decision

A new domain, **`src/fractions/`**, with three exports. The text below is written on the
recommended option of every owner decision, assumed until the owner picks.

### The domain

- Folder `src/fractions/`, holding `fractions.ts`, `fractions.test.ts` and `index.ts`
  (`export * from "./fractions"`). No `types.ts`: no export takes an options object.
- `src/nepali-number.ts` adds `export * from "@/fractions"`.
- It may import `@/constants`, `@/conversion` and `@/words`. **Nothing imports it.** It is a
  leaf beside the existing chain
  `constants ← conversion ← formatting ← utils ← words ← currency`.
- Its language data goes in `src/constants.ts` (invariant 6): the quarter-step words, the
  prefixes `सवा`, `साढे`, `पौने`, the connector `बटा`, the multipliers and `गुणा`.

### `toNepaliFraction(value: NumericInput): string`

The spoken form for a value that is a whole number of quarters; otherwise the plain words.

| Value | Output |
|---|---|
| `0.25` | `"पाउ"` |
| `0.5` | `"आधा"` |
| `0.75` | `"तीन पाउ"` |
| `1.25` | `"सवा"` |
| `1.5` | `"डेढ"` |
| `1.75` | `"पौने दुई"` |
| `2.25` | `"सवा दुई"` |
| `2.5` | `"अढाई"` |
| `2.75` | `"पौने तीन"` |
| `3.5` | `"साढे तीन"` |

The rule, for a whole part *n*:

- *n* + ¼ → `"सवा <n>"` for *n* ≥ 2; `1.25` is `"सवा"` alone; `0.25` is `"पाउ"`.
- *n* + ½ → `"साढे <n>"` for *n* ≥ 3; `0.5`, `1.5` and `2.5` have their own words.
- *n* + ¾ → `"पौने <n+1>"` for *n* ≥ 1; `0.75` is `"तीन पाउ"`.
- `<n>` is `toNepaliWords(n)`, so it works at any size: `100.5` → `"साढे एक सय"`.
- An integer → `toNepaliWords(value)`. Any other value → decimal words (`1.3` →
  `"एक दशमलव तीन"`, ADR-0014).
- Negative → `"ऋण "` and the form for the absolute value. Zero → `"शून्य"`.
- Invalid → `""`.

Trailing fraction zeros do not matter: `"1.50"` is `1.5`.

### `toNepaliFractionWords(numerator: NumericInput, denominator: NumericInput): string`

A fraction read the way it is read aloud in school arithmetic: numerator, `बटा`, denominator.

| Call | Output |
|---|---|
| `(2, 5)` | `"दुई बटा पाँच"` |
| `(1, 2)` | `"एक बटा दुई"` |
| `(3, 4)` | `"तीन बटा चार"` |
| `(7, 3)` | `"सात बटा तीन"` |
| `(-2, 5)` | `"ऋण दुई बटा पाँच"` |

It never simplifies and never switches to a spoken form: `(1, 2)` is `"एक बटा दुई"`, not
`"आधा"`. A denominator of zero, a negative denominator, a non-integer in either place, or
invalid input returns `""`.

### `toNepaliMultiplier(times: NumericInput): string`

| Value | Output |
|---|---|
| `1` | `"एक गुणा"` |
| `2` | `"दोब्बर"` |
| `3` | `"तेब्बर"` |
| `4` | `"चौबर"` |
| `5` | `"पाँच गुणा"` |
| `100` | `"एक सय गुणा"` |
| `2.5` | `"दुई दशमलव पाँच गुणा"` |

2, 3 and 4 have their own word; every other positive value is `toNepaliWords(times)` followed
by `गुणा`. Zero, a negative value or invalid input returns `""`.

## Options considered

| Option | Pros | Cons | Verdict |
|---|---|---|---|
| A — A new `fractions` domain with three exports | The data and its tests sit together; nothing existing changes; tree-shakes away for consumers who don't use it | A sixth domain to keep in the architecture document | Chosen |
| B — Put the three exports in `words` | No new folder | `words.ts` already grows a lot in ADR-0014; mixes two reviews of language data | Rejected |
| C — An option on `toNepaliWords` (`{ fractions: true }`) | One function to learn | Changes what an existing export means; `0.5` → `"आधा"` would surprise a consumer expecting decimal words; no place for `बटा` or multipliers | Rejected |
| D — Leave it to consumers | No language data to review | Every consumer rewrites the same table, each with its own spellings | Rejected |

### Owner decisions

The recommended column is what this ADR and the API page are written on. **None of these forms
was checked against a reference by the drafting agent.**

| Decision | Options (actual output) | Recommended | Consequence |
|---|---|---|---|
| ¼ on its own | `0.25` → `"पाउ"` · `"चौथाई"` · `"एक चौथाई"` | `"पाउ"` | `पाउ` is also a weight; `चौथाई` is the written, formal form |
| ½ on its own | `0.5` → `"आधा"` · `"आधी"` | `"आधा"` | One invariable form; no gender agreement |
| ¾ on its own | `0.75` → `"तीन पाउ"` · `"पौने"` · `"तीन चौथाई"` | `"तीन पाउ"` | `पौने` alone is unusual without a number after it; `तीन चौथाई` is formal |
| 1¼ | `1.25` → `"सवा"` · `"सवा एक"` | `"सवा"` | `सवा` alone means one and a quarter; `सवा एक` matches the general rule |
| 1½ | `1.5` → `"डेढ"` · `"डेढ़"` · `"साढे एक"` | `"डेढ"` | `डेढ़` carries the Hindi nukta; `साढे एक` is not normally said |
| 2½ | `2.5` → `"अढाई"` · `"साढे दुई"` | `"अढाई"` | Both are heard; picking `साढे दुई` moves the `साढे` rule down to *n* ≥ 2 |
| *n* + ½ prefix | `3.5` → `"साढे तीन"` · `"साँढे तीन"` | `"साढे तीन"` | Spelling of the prefix for every half from 3½ up |
| *n* + ¼ prefix | `2.25` → `"सवा दुई"` · `"सवा दुइ"` | `"सवा दुई"` | Follows the `दुई` already in `constants.ts` |
| *n* + ¾ prefix | `1.75` → `"पौने दुई"` · `"पौने दुइ"` | `"पौने दुई"` | Names the *next* whole number, as the spoken form does |
| Quarter steps above small numbers | `100.5` → `"साढे एक सय"` · `"एक सय दशमलव पाँच"` | `"साढे एक सय"` | The first applies the rule at any size; the second stops it at a limit the owner names |
| Non-quarter values | `1.3` → `"एक दशमलव तीन"` · `""` | `"एक दशमलव तीन"` | The first always returns something readable; the second makes the function strict |
| Fraction connector | `(2, 5)` → `"दुई बटा पाँच"` · `"पाँच भागको दुई"` · `"पाँच खण्डको दुई"` | `"दुई बटा पाँच"` | `बटा` keeps the written order; `भागको` reverses it |
| Fractions with a spoken form | `(1, 2)` → `"एक बटा दुई"` · `"आधा"` | `"एक बटा दुई"` | The first is predictable; the second makes two exports overlap |
| Double | `2` → `"दोब्बर"` · `"दुई गुणा"` | `"दोब्बर"` | |
| Triple | `3` → `"तेब्बर"` · `"तीन गुणा"` | `"तेब्बर"` | |
| Quadruple | `4` → `"चौबर"` · `"चौब्बर"` · `"चार गुणा"` | `"चौबर"` | The drafting agent is least sure of this spelling |
| Other multipliers | `5` → `"पाँच गुणा"` · `"पाँच गुना"` | `"पाँच गुणा"` | Spelling of the suffix for every value except 2, 3, 4 |
| One time | `1` → `"एक गुणा"` · `""` | `"एक गुणा"` | |
| Negative fraction | `-1.5` → `"ऋण डेढ"` · `""` | `"ऋण डेढ"` | Follows `toNepaliWords`, which already prefixes `ऋण` |

## Consequences

**Positive**

- Amounts can be written the way they are spoken, from one table that has been reviewed once.
- No existing export changes: the three functions are additions.

**Negative / accepted trade-offs**

- More language data to keep correct. A wrong form here ships to every consumer, which is why
  each one is an owner decision.
- The minified build grows. The size is measured at implementation and recorded here
  (invariant 8); the domain tree-shakes away in the ESM build for consumers who don't import it.
- Only quarter steps get a spoken form. Thirds (`तिहाई`) and other fractions are not covered;
  `toNepaliFractionWords` reads them as `बटा`.

**For consumers**

- Nothing existing changes. Three new named exports from the package root, and on the global
  `nepaliNumber` in the browser builds.

## Package invariants

- **1, 2, 3** — no dependency, no host global, pure functions of their arguments.
- **4** — every export returns `""` for input it cannot handle, including a zero denominator;
  none throws. `null` and `undefined` follow ADR-0012.
- **5** — no existing output changes. The new strings become contract on release.
- **6** — every Devanagari string lives in `src/constants.ts`; `fractions.ts` hardcodes none.
- **7** — no character walking: the values come from ADR-0012's reader as ASCII digit strings.
- **8** — named exports only; the build grows, measured at implementation.
- **Layering** — a new leaf domain that imports downward only (`constants`, `conversion`,
  `words`) and is imported by nothing. No cycle.

## Security considerations

- **Input parsing:** none of its own. All three exports read their arguments through
  ADR-0012's reader, whose behaviour on empty, whitespace, huge, `NaN`, `Infinity` and
  non-digit input is defined there. This domain adds no regular expression.
- **Hostile input:** a 100 000-character digit string is a valid, very large number; the
  quarter test looks only at the fraction digits and the words are built in time linear in the
  length. A test covers it.
- **Dependencies, CI, publishing:** unchanged. No dependency, no workflow change, no change to
  `package.json`.
