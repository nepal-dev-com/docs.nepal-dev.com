The library itself reads **no** secrets, environment variables or configuration. Secrets exist
only in GitHub Actions.

| Secret | Used by | Purpose | Scope / risk if leaked |
|---|---|---|---|
| `CODECOV_TOKEN` | `ci.yml`, `quality` job, Node 24 | Upload `coverage/lcov.info` to Codecov | Can upload coverage reports for this repository; cannot change code or publish. Stored twice: as an Actions secret, and as a Dependabot secret, because a run started by Dependabot reads only Dependabot secrets |
| `GITHUB_TOKEN` | `release.yml`, `release-please` job | Automatic per-run token; open and update the release pull request, push the tag, create the GitHub release | `contents: write`, `pull-requests: write` and `issues: write` on this repository for the duration of the run |
| OIDC identity token | `release.yml`, `publish` job | Prove to npm that the run is this repository's `release.yml` in the `npm` environment (trusted publishing) | Not stored: GitHub issues it for one run (`id-token: write`), and npm exchanges it for a publish that is valid for minutes |
| `GITHUB_TOKEN` | `codeql.yml` | Automatic per-run token; read the code and upload scan results | `contents: read` and `security-events: write` for the duration of the run |

**No npm token exists**, and none is created. Publishing uses npm trusted publishing, and token
publishing is disallowed for the package on npmjs.com ([ADR-0020](../adr/ADR-0020-release-with-release-please-and-npm-trusted-publishing.mdx)).

## Rules

- **No secret is ever a literal** — not in source, workflows, comments, tests or docs.
- **Secrets are referenced only as `${{ secrets.NAME }}`** and never echoed or written to files
  that are uploaded as artifacts.
- **If a secret is ever committed or printed in a log, rotate it immediately.** Removing it from
  the tree or the history is not enough.
