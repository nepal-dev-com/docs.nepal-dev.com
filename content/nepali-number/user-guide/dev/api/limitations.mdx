## Functions that return a `number` lose precision on very large values

Reading and formatting are exact at any size: digits are handled as decimal strings. A function
whose **return type** is `number` still has to fit the result into a JavaScript number, which
holds integers exactly only up to 9 007 199 254 740 991.

```ts
toNepaliWords("9007199254740993")       // exact: the words end in "…त्रियानब्बे"
parseNepaliNumber("9007199254740993")   // → 9007199254740992
```

**Workaround.** Keep large values as strings or `bigint`s and pass them straight to the
formatting and word functions.

## A `number` argument has already been rounded by JavaScript

The package reads the shortest decimal that JavaScript prints for a `number`. Arithmetic done
before the call has already lost digits.

```ts
formatNepaliNumber(0.1 + 0.2, { precision: 20 })    // → "०.३०००००००००००००००४०००"
formatNepaliNumber("0.3", { precision: 20 })        // → "०.३०००००००००००००००००००"
```

**Workaround.** Keep money as integer paisa, or pass decimal strings.

## Invalid input returns an empty result, not zero

Input that is not a number returns `NaN` from functions that return a number, `""` from
functions that return a string, and `false` from checks. Zero is returned only for zero.

```ts
parseNepaliNumber("abc")        // → NaN
formatNepaliNumber("12abc")     // → ""
toNepaliWords("")               // → ""
```

**Workaround.** `formatNepaliNumber(value) || "०"` where a zero fallback is wanted.

## Character converters do not validate

`toNepali`, `toEnglish` and `convert` map digits character by character and leave everything
else alone, so they accept any text.

```ts
toNepali("12abc")               // → "१२abc"
```

**Workaround.** `isValidNumber(input)` first when the input must be a number.

## Ordinals need whole numbers

There is no ordinal of `12.5`.

```ts
toNepaliOrdinal(12.5)           // → ""
toEnglishOrdinal(12.5)          // → ""
```

**Workaround.** `toNepaliOrdinal(Math.trunc(n))`.

## A sign is never read inside prose

In a sentence a hyphen is more often a separator than a minus, so the text functions read
`"-5"` as `5`.

```ts
extractNumbers("तापक्रम -5 डिग्री")     // → [5]
extractNumbers("9841-123456")         // → [9841, 123456]
```

**Workaround.** Use [`findNumbers`](./text.mdx#findnumberstext) and look at
`text[match.index - 1]`.

## Unit conversions are floating point

Traditional units convert through fixed factors that are not round in metric, so results carry
binary floating-point digits.

```ts
convertLandArea(1, "ropani", "sqm")     // → 508.73704704
```

**Workaround.** Round for display with
[`roundNepali`](./utils.mdx) or `formatNepaliNumber`.

## `validateNepaliNumber` rejects English digits

It checks that a number is written in Nepali digits.

```ts
validateNepaliNumber("123")     // → false
isValidNumber("123")            // → true
```

**Workaround.** Use `isValidNumber` to accept either script.
