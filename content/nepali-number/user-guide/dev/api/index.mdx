> Every output on these pages was produced by running the built package.

Every export is a named, pure function, imported from the package root:

```ts
import { toNepali, formatNepaliNumber, toNepaliWords } from "nepali-number"
```

There is no default export and no sub-path import. In the browser builds the same functions
hang off the global `nepaliNumber` ([getting started](../getting-started.mdx)).

## Behaviour that holds across the API

- **Numbers are read once, exactly.** `NumericInput` is `number | bigint | string`. Digits are
  handled as decimal strings, so formatting and words are exact at any size
  ([how a number is read](./conversion.mdx#how-a-number-is-read)).
- **Both digit systems are accepted everywhere** a number is read: `"123"`, `"१२३"` and mixed
  `"12३"` are the same number.
- **Invalid input never throws, and never reads as zero.** A function that returns a number
  returns `NaN`, one that returns a string returns `""`, a check returns `false`, a list is
  empty.
- **Rounding is half away from zero** on the decimal digits as written: `1.005` at two places
  is `1.01`.
- **Grouping is Nepali** by default: the last three digits, then pairs — `1,23,45,678`.
- **Scales** used by words and abbreviations, from `src/constants.ts`:

  | Value | Nepali | English label | Ordinal |
  |---|---|---|---|
  | 10² | सय | hundred | सयौं |
  | 10³ | हजार | thousand | हजारौं |
  | 10⁵ | लाख | lakh | लाखौं |
  | 10⁷ | करोड | crore | करोडौं |
  | 10⁹ | अर्ब | arab | अरबौं |
  | 10¹¹ | खर्ब | kharab | खरबौं |
  | 10¹³ | नील | neel | नीलौं |
  | 10¹⁵ | पद्म | padma | पदमौं |
  | 10¹⁷ | शंख | shankh | शंखौं |
  | 10¹⁹ | महाशंख | maha-shankh | महाशंखौं |

Read [**limitations**](./limitations.mdx) before relying on edge-case behaviour.
